## Architecture Notes

### Auth (Google Sign-In) — `src/auth.ts` + `src/components/blog/user-menu.tsx`
- Stack: `next-auth@5.0.0-beta.32` (Auth.js v5). `src/auth.ts` exports `{ handlers, auth, signIn, signOut } = NextAuth({ providers: [Google] })`; with no explicit `clientId`/`clientSecret` the Google provider reads `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` from the environment itself — the same variables Vercel must carry in Production/Preview alongside `AUTH_SECRET` (JWT signing key, now generated in `.env.local`).
- **Sessions are JWT, standalone by design** (no `adapter` configured → no database touchpoint, the email/password half of `AuthForm` remains a local simulation). Attaching the separate application database later is the 3-step recipe documented in the `src/auth.ts` header: fill `DATABASE_URL` (commented placeholder at the bottom of `.env.local`), install an Auth.js adapter (`@auth/pg-adapter`, `@auth/drizzle-adapter`…), pass `adapter:` to `NextAuth()` — no call site changes.
- Route: `src/app/api/auth/[...nextauth]/route.ts` re-exports `GET`/`POST` from `handlers`; the build lists it as `ƒ /api/auth/[...nextauth]`. In the Google Cloud Console the authorized redirect URI is `<origin>/api/auth/callback/google`.
- `SessionProvider` (from `next-auth/react`) is mounted in `src/app/layout.tsx` **around** `TranslationProvider`; a server `layout.tsx` rendering the client provider is the standard boundary.
- `user-menu.tsx` (client) is the masthead account slot: `status === "loading"` → quiet skeleton chip (no layout jump); anonymous → the previous `Connexion` text link; authenticated → the Google avatar via `next/image` (`lh3.googleusercontent.com` whitelisted, object form, `pathname: "/**"`), the reader's first name as a home link, and a `LogOut` disc calling `signOut({ callbackUrl: "/" })`. Avatars without an image URL fall back to an indigo monogram disc (`initialsOf`). Labels: `auth.login` / `auth.myAccount` / `auth.signOut`. **No admin entry point anywhere in the public chrome** — the Phase 22 amendment deleted the "Espace Admin" link, its `AdminNavLink` component and the `useAdminSession` hook from both the masthead and the drawer; the back-office lives at `/admin/login` + `/admin/dashboard`, reachable by typing the URL directly.
- `auth-form.tsx`: the Google row (`signIn("google", { callbackUrl: "/" })` wrapped in try/catch → inline `role="alert"` failure note above the CTA links) sits under an `ou` separator after the simulated email/password submit. The Google mark is an inline four-path SVG — `lucide-react` ships no brand glyphs (same reasoning as the share-button wordmark pills). The demo note now reads "E-mail + mot de passe : simulation locale. Google : connexion réelle via Auth.js."

### Data layer — `src/lib/wordpress.ts` (server only)
- `getHomePageData()` / `getPosts({ first, categoryId, categoryName, search, authorName, language })` / `getPostBySlug(slug, language?)` / `getCategories()` / `getAuthorBySlug(slug)` / `getPostsByAuthor(slug, first)`.
- **Never throws.** Every failure (transport, HTTP, GraphQL) resolves to an empty/`null` result plus an `error` string; the UI renders a designed empty state instead of crashing. `getPostBySlug` distinguishes "not found" (`post: null, error: null` → `notFound()`) from "CMS down" (`error !== null` → degraded notice). Same contract for `getAuthorBySlug` (`author: null, error: null` → 404) and `getPostsByAuthor`.
- Normalisation: HTML stripped + entities decoded for excerpt/title, reading time derived from word count (200 wpm), `tags` normalised with `isPremium` derived from the `premium` slug, deterministic Unsplash fallback image (FNV-1a over the slug) when `featuredImage` is `null`. Every post now also carries `authorSlug` (WP nicename, falling back to `slugifyAuthorName(display name)`), which builds `/blog/author/[slug]` links everywhere.
- Listing queries are generated by `buildPostsQuery()` — one dynamic document that emits `categoryId` / `categoryName` / `search` / `authorName` / `language` (`LanguageCodeEnum`) `$variables` + `where` args only when present (replaces the old four-query matrix; adding a filter is now one `if` block). `PostCategory` gained `id` (WP term `databaseId`) and `count`; `getCategories()` orders by count and feeds the sidebar index **and** the home-page desk resolution (by id — see Decisions).
- Author archives: `getAuthorBySlug` tries the WPGraphQL `user(id, idType: SLUG)` query first, then falls back to deriving the profile (name + slug) from the author's latest story; `getPostsByAuthor` tries the `authorName` where arg, then falls back to a slugified-name scan of the newest posts. Both degrade to `error` strings when the CMS is down.
- **`PostSummary` is the client boundary** (Phase 11): `type PostSummary = Omit<Post, "content"> & { content?: never }` plus `toPostSummary()` / `toPostSummaries()`. Every prop handed to a client component is serialised into the RSC payload, so passing a full `Post` shipped the article HTML twice and — because the article body is the paywalled asset — let a locked Premium story be read straight out of the payload. The `content?: never` intersection makes a raw `Post` **unassignable** to a `PostSummary`, so `tsc` fails on any new leak; server components that render the body keep using `Post`, and everything crossing the boundary goes through the helper. Callers: `HeroSection`, `PostCard`, `ArticleHeader`, `Sidebar`/`SidebarWidgets`, `RelatedPosts`, `CategorySection`.
- Transport hardening: `fetchGraphQL` wraps `fetchGraphQLOnce` with **one** retry (800ms delay) for transport failures and non-2xx HTTP only — GraphQL-level errors are deterministic and never retried. This stops a Pantheon cold start or a build-time burst from baking an empty state into a statically rendered page.
- Phase 1 seeding: `scripts/seed-wordpress.js` (Node 20+, zero dependency) injects `scripts/seed-data/batch1-7.js` (28 stories) via WP REST with Basic auth (`WP_USERNAME` + `WP_APP_PASSWORD`, `--dry-run` / `--limit` / `--skip-media` / `--batch` + `--batch-size` flags, idempotent by slug). Creates the 4 desks + the `premium` tag when missing, sideloads each Unsplash cover into the media library, tags 9 stories Premium (32 percent). `scripts/backfill-media.js` re-attaches covers still missing. Credentials live only in the shell env, never in the repo.
- Caching: `fetch(..., { next: { revalidate: 3600, tags: ["wordpress:posts"] } })`; 10s `AbortSignal.timeout` so a stalled CMS cannot block a render.
- Endpoint override: `NEXT_PUBLIC_WORDPRESS_API_URL` env var first, then legacy `WORDPRESS_GRAPHQL_ENDPOINT`, then the built-in Pantheon default (add the new host to `images.remotePatterns` too). See `DEPLOYMENT.md` for the Vercel setup.
- Search filter: `getPosts({ search })` maps the trimmed query onto the WPGraphQL `search` where arg (standalone or combined with any other filter); empty queries are dropped so plain listings keep the base query. `/api/search` (dynamic route, `GET ?q=&limit=`) wraps it for the client dialog and returns a light payload (`id/slug/href/title/excerpt/publishedAt/readingTime/category`) with the same never-throw contract.

### Theme (light / dark) — `next-themes`
- `src/components/theme-provider.tsx` (client) wraps the app **inside** `<body>` in `src/app/layout.tsx` (`ThemeProvider > MotionConfig > SessionProvider > TranslationProvider` since Phase 21) with `attribute="class"`, `defaultTheme="dark"`, `enableSystem={false}`, `themes={["light","dark"]}` and `disableTransitionOnChange`; `<html>` carries `suppressHydrationWarning` because `next-themes` writes the theme class before React hydrates.

### Article body splitting — `src/lib/article.ts`
- `splitArticleContent(html, { paragraphCount, maxChars })` cuts the CMS body after the n-th top-level `</p>` and returns `{ intro, body }`; `GATED_INTRO_PARAGRAPHS = 1`, `INTRO_PARAGRAPHS = 2` and `GATED_INTRO_MAX_CHARS = 700`. It is dependency-free on purpose: WPGraphQL returns block markup where every paragraph is a top-level `<p>`, so counting closing tags is reliable and no HTML parser ships to the server bundle.
- **The character ceiling exists because of WordPress auto-excerpts:** plenty of stories are a single paragraph, and for those "the first paragraph" *is* the whole article — the gate would have revealed everything. When the intro exceeds the cap it is reduced to plain text on a word boundary inside one `<p>` with an ellipsis (a single long word is kept rather than erased).
- `hasDistinctExcerpt(excerpt, introHtml)` returns `false` when the CMS excerpt is just the opening of the body, and the route forwards it to `ArticleHeader`'s `showStandfirst` so the reader never reads the same sentence twice (the auto-excerpt also spills past the first paragraph, which matters on gated stories).

### i18n — `src/lib/i18n/` (FR / EN / DE)
- `index.tsx` (client) owns the system: `TranslationProvider` (mounted in `src/app/layout.tsx` around `{children}`), `useTranslation()` (`t`, `tList`, `locale`, **`setLocale`**), the `Locale` type, `LOCALES`, `DEFAULT_LOCALE` (`fr`), `LOCALE_NAMES` and `SUPPORTED_LOCALES`. **The file must keep the `.tsx` extension** — it renders `<TranslationContext.Provider>` and TypeScript rejects JSX in `.ts`.
- **Dictionaries are static JSON imports** (`import fr from "./locales/fr.json"`), not `require()`: the project's ESLint config rejects `require()` style imports, and all three files were already bundled together, so nothing changed size-wise. The provider reads the persisted choice through **`useSyncExternalStore`** (`subscribeToLocale` + `readStoredLocale` + `getServerLocale`) instead of a `useEffect` that called `setState` — the server and the hydration render both get `DEFAULT_LOCALE` (FR, no hydration mismatch) and the stored/browser language is applied right after. `setLocale(next)` sets a local override, writes `localStorage["techpulse-locale"]` and dispatches a `techpulse:locale` event (the store also listens to `storage`, so other tabs follow). A `useEffect` keeps `document.documentElement.lang` in sync.
- **`{{s}}` plural marker:** the count labels place the plural suffix themselves (`{{count}} story{{s}}`), and `t()` resolves it against `params.count` (`1` drops the suffix). Before this the archive header printed the literal `{{s}}`; `t(key)` without params now defaults to the plural form. Also note `t()` fills params with `split`/`join`, so a param used twice is replaced twice.
- Dictionaries: `locales/fr.json`, `locales/en.json`, `locales/de.json` — **13 top-level sections / 263 leaf values each, verified in strict parity by script** (same key sets, no extras/missing; Phase 22 added the new `terms` section — 21 keys — and five `header.feed*` keys for the live-feed dialog, on top of the Phase 11 growth from 226 to 235 with `nav.aiCloud`, `header.themeLight` / `header.themeDark`, `blog.sidebar.ariaLabel` and the five `blog.author.*` keys). The `notFound` section (eyebrow / title / body / categoriesHeading) and `header.menu` came with the UX hardening pass; the Phase 7 auth pass added `auth.myAccount` / `auth.signOut`; Phase 8 added `auth.dashboard.*`; Phase 9 added the whole `privacy` section (17 keys) plus `auth.dashboard.greeting`, `subscribe.submitting` and `subscribe.checkoutError`. `tList()` returns translated string arrays (`blog.sidebar.benefits`, `paywall.benefits`, `subscribe.*Features`…), `t(key, params)` interpolates `{{param}}` tokens, and both `console.warn` + return the key itself on a miss (so a missing key can never crash a render).
- Locale resolution: the first paint renders **FR on server *and* client** (no hydration mismatch); the stored `localStorage["techpulse-locale"]` value, then `navigator.language`, then the French default are read through `useSyncExternalStore` right after hydration. The `LanguageSelector` calls `setLocale()` from the context, so switching FR / EN / DE re-renders every translated string **in place — no `window.location.reload()`** and no lost scroll position; the provider persists the choice to the same `localStorage` key and updates `<html lang>`.
- Server components translate through the `<T k="…" params={…} />` leaf (`src/components/blog/t.tsx`) — only that tiny client component crosses the boundary, which is how the article page, category page, `/blog` archive, `PostCard` and `ArticleHeader` get translated strings while staying server-rendered. Client components (`SiteHeader`, `SiteFooterContent`, `SearchDialog`, `PaywallBanner`, `SidebarWidgets`, `RelatedPosts`, `ShareButtons`, `CommentsSection`, `ContactForm`) call `useTranslation()` directly.
- Cost/trade-off accepted: converting `SidebarWidgets`/`RelatedPosts`/`PaywallBanner` to client components moved their markup into the client bundle; the alternative (cookie-based server locale) would have required a server round-trip per switch and breaks on the statically prerendered pages. Because a client component's props travel in the RSC payload, everything crossing that boundary now carries a `PostSummary` instead of a `Post` (see Decisions).
- Known gaps (deliberate): CMS content (post titles, excerpts, bodies, category names, desk descriptions in `CATEGORY_INDEX`) is editorial data and stays untranslated **until the CMS carries a WPML / Polylang GraphQL bridge** — the plumbing is ready: `normalizeLanguageCode()` + `language` on `getPosts` / `getPostBySlug` (see Data layer) resolve the translated post when the bridge exists and retry unfiltered when it does not, so wiring the reader's UI locale (`useTranslation().locale`) into those calls is the only step left; `/about`, `/login`, `/register`, `/contact` chrome and the home page desk bands still hold their original copy — the dictionary keys exist, so migrating them is purely mechanical `<T />` substitution. `/subscribe`, `/privacy` and `/dashboard` are **fully translated** (server components + `<T />` leaves).

## Decisions & Gotchas
- **React #418 (hydration mismatch) came from `useReducedMotion()` reading the browser during hydration — never branch motion props on a browser value in render.** Verified against the installed source (framer-motion 13 + motion-dom): `useReducedMotion` runs `initPrefersReducedMotion()` on the first client render, which synchronously reads `window.matchMedia("(prefers-reduced-motion)")`, while the server render leaves the shared state at `null`. The three animated components branched their props on that value (`reveal()` collapsed to `{}` for reduced-motion readers; `PostCard` swapped `initial={false}` / `whileInView={undefined}`), so a reduced-motion reader hydrated different `style` attributes (`style="opacity:0;…"` present server-side, absent client-side) — React 19 reports that as the minified production error #418. Only readers with the OS "reduce motion" setting hit it, which is why it looked intermittent. The fix has three hydration-safe layers: (1) the motion props are deterministic literals again (`initial`/`animate`/`whileInView` never depend on render-time browser state, `useReducedMotion` is gone from render); (2) `<MotionConfig reducedMotion="user">` is mounted in `src/app/layout.tsx` around the whole app — framer's official mechanism, and provably markup-safe because `visualElement.shouldReduceMotion` is only read in the animation/projection paths, never in the style-building path (so the SSR HTML and the hydration render are byte-identical); (3) the `[data-motion-reveal]` guard in `globals.css` (`opacity: 1 !important; transform: none !important` inside the `prefers-reduced-motion` media block) keeps the stricter "static content for reduced-motion readers" contract without any JS — an author-stylesheet `!important` beats framer's non-important inline styles. Every animated `motion.*` element carries `data-motion-reveal`. Two same-class latent mismatches were hardened in the same pass: the admin activity stamp (`timeAgo()` recomputes `Date.now()` per render and can flip across a minute boundary between SSR and hydration — the `<time>` carries `suppressHydrationWarning`) and the footer copyright year (`getFullYear()` on both sides of a static-cache boundary across New Year's midnight — the `<p>` carries `suppressHydrationWarning`).
- **The paywall is decided on the server, and that is why `/blog/[slug]` is dynamic.** `cookies()` is a request-time API, so reading the Premium markers opts the route into dynamic rendering (`ƒ`). The alternative — a statically cached article — would have served one cached HTML to everyone: a subscriber's unlocked body handed to anonymous readers, or the paywall handed to a subscriber. The CMS fetches keep their own 1h data cache, so the cost is the React render, not a WordPress round-trip.
- **Two of the three unlock signals are cookies, and `?success=true` is the third.** `techpulse_premium` (httpOnly, 30 days) is the real marker, `techpulse_premium_success` (10 min, non-httpOnly) rides along with the checkout redirect, and the query flag covers the instant between the redirect and the cookie being readable. All three are checked with OR — never trust a client-side check, the gate is server-rendered.
- **Props travelling to a client component are public.** `ArticleHeader`, `PostCard`, `Sidebar`, `RelatedPosts` and `HeroSection` are client components, and every prop they receive is serialised into the RSC flight payload — so passing a full `Post` published the article HTML to the browser *even when the page only rendered the first paragraph*. This was the single biggest paywall hole and it also bloated each archive page by the whole newsroom's markup. The fix is `PostSummary` (`Omit<Post,"content"> & { content?: never }`) plus `toPostSummary()` / `toPostSummaries()` at every call site; the `never` intersection is what makes `tsc` catch the next leak instead of a code reviewer.
- **`splitArticleContent` cuts on `</p>`, and the character cap is not optional.** WordPress auto-excerpts mean many posts are one single paragraph; with only the paragraph rule, a locked Premium story would render its entire body as "the first paragraph". `GATED_INTRO_MAX_CHARS` (700) also protects the page from a 3 000-character opening paragraph, and `hasDistinctExcerpt` hides the standfirst when the CMS excerpt merely repeats the intro.
- **No sidebar card may be `sticky`.** The rail used `lg:sticky lg:top-8` while the widgets stacked below it in the same column, so it scrolled over the Premium upsell / desk index cards instead of moving with them. Sticky is now gone everywhere except the masthead, and the single `<Sidebar />` wrapper (own `lg:col-span-4`, `flex flex-col gap-6`) is the only place a sidebar is composed. Note the old category-page markup also wrapped the sidebar in `hidden lg:flex`, which removed it entirely on phones — the shared wrapper must not reintroduce that.
- **`useSyncExternalStore` (not an effect) is how the i18n provider reads `localStorage`.** The previous mount effect called `setState` synchronously, which `react-hooks/set-state-in-effect` rejects and which caused a cascading render on every load. `subscribeToLocale` + `readStoredLocale` + `getServerLocale` gives a hydrated FR first paint and then applies the stored language, with cross-tab `storage` support for free. The dictionaries are static JSON imports because this project's ESLint config forbids `require()`.
- **Language switching no longer reloads the page.** `LanguageSelector` calls the context's `setLocale`; the provider persists the choice and updates `<html lang>`. Anything that *must* be re-rendered by the server (page metadata, the CMS content language) is still English/editorial by design — CMS copy is data, not UI chrome.
- **`text-[#a5b4fc]` is banned in favour of `text-link`.** Light/dark theming cannot survive hard-coded accent hexes: indigo-300 on white fails contrast, so the accent is a token (`--figma-link`: `#a5b4fc` dark / `#4338ca` light) and `ARTICLE_PROSE_CLASSES` uses `prose dark:prose-invert` rather than a hard-coded `prose-invert`. When adding accent text, use `text-link`.
- **`next-themes` needs the dark default to be the CSS default.** The Figma palette sits on `:root`, so the pre-hydration paint is already dark; `defaultTheme="dark"` + `enableSystem={false}` means the toggle is an explicit two-state switch and no reader is silently handed a theme they never chose. `theme-toggle.tsx` deliberately renders from `resolvedTheme` with a dark fallback and knows nothing about `mounted` — a `setState` in an effect would trip the lint rule again.
- **The subscription state lives in two cookies, not a database.** `techpulse_premium_success` is deliberately **non-httpOnly** (the dismiss button in `PremiumSuccessBanner` clears it with `document.cookie`) while `techpulse_premium` is **httpOnly** so only the server can mint it. Reading the premium marker with `await cookies()` forces `/dashboard` to stay dynamic (`ƒ`) — that is correct, a statically cached member area would leak one reader's tier to another.
- **`subscribe-feature-list.tsx` needs `"use client"` even though it renders a plain `<ul>`.** It calls `useTranslation()`, and the first Phase 9 build failed with `Attempted to call useTranslation() from the server but useTranslation is on the client` while prerendering `/subscribe`. Any component that calls `useTranslation` / `tList` must be a client component; a **server** component must go through the `<T />` leaf instead. Getting this backwards only surfaces at build time, not in `tsc`.
- **`PremiumSuccessBanner` must stay inside a `<Suspense>` boundary.** It calls `useSearchParams()`, which forces client-side rendering up to the nearest boundary — without `<Suspense fallback={null}>` the dashboard route would bail out of prerendering. The banner is triggered by **either** `?success=true` **or** the success cookie, so the confirmation survives the redirect *and* a refresh.
- **The mock checkout reads the session through the route module, not directly.** `src/app/api/stripe/checkout/route.ts` imports `auth` from `@/app/api/auth/[...nextauth]/route` (re-exported there for exactly this purpose) so the Google provider config stays declared once in `src/auth.ts`. Do not `NextAuth(...)` a second time in the API route — that would fork the encryption/session config.
- **`/privacy` was a dead link before Phase 9.** The dashboard's "Politique de confidentialité" row pointed at a route that did not exist, so the link 404'd. It now resolves to a real static page, which is also linked from the shared footer. When adding a link to chrome, verify the target route exists — `tsc` does not know about route strings.
- **`PLAN_PRICES` in the checkout route is the single source of truth for what the sandbox charges** (monthly 9,99 €, yearly 89,99 €). The prices printed on `/subscribe` come from the locale (`subscribe.pricingMonthly` / `pricingYearly` with a `params` price) and are display copy only — if the route's numbers change, the locale strings must be updated to match.
- **The AI & Cloud desk slug is `ai-and-cloud`, never `ai-cloud`** (verified live through GraphQL: term id 13, slug `ai-and-cloud`, name `AI & Cloud`, 6 posts). The home page used to hand the short shape to the desk "Tout voir" link, and `/blog/category/ai-cloud` fell through `resolveCategory` to `notFound()` — a home-page link that 404s. The link now carries the real slug and `next.config.ts` answers the legacy shape with a permanent 308 (same pattern as `/posts/:slug`). Slug sources of truth: `navigation.ts` (tech-news, development), the live `getCategories()` slugs in the sidebar index, and the four hardcoded desks in `not-found.tsx` (tech-news, development, design, ai-and-cloud).
- **The root 404 is `src/app/not-found.tsx`** (server component + `<T />` leaves): oversized gradient 404 badge, translated title/body (`notFound.*` keys), "Retour à l'accueil" + "Toutes les stories" CTAs and a "Rubriques principales" pill row over the four verified desks. It mounts `SiteHeader`/`SiteFooter` for full magazine chrome inside the root layout, exports no metadata (Next injects `robots: noindex` for 404s itself) and makes **no CMS calls** — a CMS outage can never break the 404.
- **`backdrop-blur-md` on the masthead creates a CSS containing block.** Any `position: fixed` descendant of `<header>` is positioned against the header box, not the viewport. The `MobileMenu` drawer therefore mounts as a sibling of `<header>` via a fragment in `SiteHeader`. The existing `SearchDialog` overlay survives the same trap only because its `min-h-screen` overlay still spans the viewport from the header's top edge — do not "simplify" the drawer back into the header.
- **`react-hooks/set-state-in-effect` (Next 16 lint) forbids synchronous `setState` in effect bodies.** The drawer's dismiss-on-desktop behaviour must live entirely inside the `matchMedia` `change` listener callback; an `if (media.matches) setState()` fast-path in the effect body fails lint (hit during this pass, removed). Same class of trap as the containing-block rule above: the drawer state stays in the header, the media query only reacts to changes.
- **JSX comments only work in children position.** A `{/* … */}` comment dropped between a ternary's `(` and its JSX branch (expression position) parses as an object literal and breaks the file (`')' expected`). It happened while annotating the category-page grid; the comment now sits above the ternary.
- **WPGraphQL `categoryName` misses term names containing `&`** (verified live: `categoryName: "AI & Cloud"` returns 0 posts while the category holds 6 — WordPress stores the name encoded, so the display-name lookup never matches; `categorySlug` is not a supported where arg). The fix: `getCategories()` now exposes the WP term `databaseId` as `PostCategory.id`, the data layer gained a `categoryId` where arg (verified returning 3 posts), and the home page resolves each desk **by term id** with a `categoryName` fallback for robustness. Keep this pattern for any future `&`-containing desk.
- **PostCard footer must stay outside the story link.** The card used to wrap cover + text + footer in one `<Link>`; adding the author link to the footer would nest anchors (invalid HTML, hydration mismatch). The footer is now a sibling with `mt-auto` pinning — do not move it back inside the link.
- **Transient CMS failures can bake an empty state into static pages.** Build 1 rendered `/` without any desk section because three concurrent desk queries failed during the 51-page prerender burst (Pantheon cold start) while every other query succeeded — the page is static, so the gap persisted. `fetchGraphQL` now retries transport/HTTP failures once after 800ms, and the affected pages self-heal via the 1h ISR window either way. When a section is inexplicably missing from a build, check the live CMS first, then rebuild.
