## Architecture Notes

### Data layer — `src/lib/wordpress.ts` (server only)
- `getHomePageData()` / `getPosts({ first, categoryName })` / `getPostBySlug(slug)` / `getCategories()`.
- **Never throws.** Every failure (transport, HTTP, GraphQL) resolves to an empty/`null` result plus an `error` string; the UI renders a designed empty state instead of crashing. `getPostBySlug` distinguishes "not found" (`post: null, error: null` → `notFound()`) from "CMS down" (`error !== null` → degraded notice).
- Normalisation: HTML stripped + entities decoded for excerpt/title, reading time derived from word count (200 wpm), deterministic Unsplash fallback image (FNV-1a over the slug) when `featuredImage` is `null` — which is currently the case for **all** posts.
- Caching: `fetch(..., { next: { revalidate: 3600, tags: ["wordpress:posts"] } })`; 10s `AbortSignal.timeout` so a stalled CMS cannot block a render.
- Endpoint override: `NEXT_PUBLIC_WORDPRESS_API_URL` env var first, then legacy `WORDPRESS_GRAPHQL_ENDPOINT`, then the built-in Pantheon default (add the new host to `images.remotePatterns` too). See `DEPLOYMENT.md` for the Vercel setup.

### Design tokens — `src/app/globals.css`
- Raw Figma palette in `:root` (`--figma-background #0F172A`, `--figma-surface #1E293B`, `--figma-primary #4F46E5`, `--figma-text #F8FAFC`, `--figma-muted #94A3B8`); `.dark` mirrors it (dark is the product default).
- Semantic shadcn tokens map onto the palette, so `bg-background`, `bg-card`, `bg-primary`, `text-muted-foreground` all follow Figma. Brand aliases: `bg-canvas`, `bg-surface`, `text-ink`, `bg-brand`/`text-brand`.
- `--font-sans` now points at `--font-geist-sans` (it previously referenced itself, so `font-sans` was a no-op).
- Tailwind Typography owns the WordPress article body. `@plugin "@tailwindcss/typography";` sits at the top of this file and the article route passes `ARTICLE_PROSE_CLASSES` — `prose prose-invert prose-indigo article-prose max-w-none` plus `prose-*` modifiers that map the typography palette onto the Figma tokens: headings/strong `text-foreground`, body/lead/lists `text-muted-foreground`, links `#a5b4fc`, `prose-code:bg-surface` and `prose-pre:bg-surface`, `prose-blockquote:border-brand prose-blockquote:bg-surface/70`, `prose-hr:border-border`, `prose-img:rounded-xl prose-img:border`, `prose-figcaption:text-center`. Bullet and ordinal colours are **not** a utility here: `src/app/globals.css` carries one unlayered `.prose.article-prose` rule that repaints the plugin's native `--tw-prose-bullets` / `--tw-prose-counters` with `var(--figma-primary)` (see Decisions). The old `.article-content` `@layer components` block is **gone** — keeping both would have meant two rule sets fighting over lists, code and quotes.

### Components — `src/components/blog/`
- `post-card.tsx` (client): indigo category badge, reading time, `<time>`, Framer Motion fade-up on viewport entry, `group-hover:scale-105` image zoom, respects `prefers-reduced-motion`. **Layout contract (do not break):** root is `flex h-full w-full flex-col justify-between`, the image frame is `aspect-[16/9] w-full shrink-0`, the title is `line-clamp-2 h-[3.5rem]` (exactly 2 × `text-lg`/1.75rem line box), the excerpt is `line-clamp-3 h-[4.5rem]` and the meta footer is `mt-auto`. These fixed heights are what keep every card in a row identical — a `margin-top`/`mt-*` utility passed through `className` would shrink the card inside its stretched grid track and clip content. Image `sizes` mirrors that grid (`(max-width: 640px) 100vw, (max-width: 1024px) 50vw, (min-width: 1536px) 25vw, 33vw`); the `1536px` entry matches `2xl:grid-cols-4` so ultrawide cards get ~25vw candidates instead of ~33vw ones.
- `hero-section.tsx` (client): full-bleed image + dark/indigo overlay, oversized `tracking-tight` headline, stagger-revealed content, `preload` on the image (`priority` is deprecated in Next 16). Box sizing lives on the inner wrapper and is **scoped to `lg:` and up** so phones keep a content-driven hero: `min-h-[380px]` with an auto height at base/sm, then `lg:h-[50vh] lg:min-h-[440px] lg:max-h-[500px]` and `xl:min-h-[460px] xl:max-h-[460px]` (locked to a controlled 460px from `xl`). Content stays pinned bottom via `justify-end`; `lg:gap-4` + `lg:p-10` and the clamps (`lg:line-clamp-3` on the headline, `lg:line-clamp-2` on the excerpt, headline `lg:text-5xl xl:text-6xl`) keep the worst-case content (~414px at `lg`, ~452px at `xl`) inside the cap.
- `article-header.tsx` (client): the article masthead — indigo category badge, reading-time eyebrow, oversized `tracking-tight` headline, standfirst, then a `border-y` byline row with the author monogram (`size-10` indigo disc), `<time>` and reading time. Reuses the `reveal()` helper, easing and `prefers-reduced-motion` escape hatch of `hero-section.tsx`, so the front page and the article page share one motion language.
- `related-posts.tsx` (server): the "recommended reading" rail. Renders an `<aside>` (id + `aria-labelledby`) with 3 compact links — `size-20` thumbnail, category eyebrow, `line-clamp-2` title, reading time — plus an "All stories" CTA. Micro-interactions are pure CSS (`transition-transform duration-500 group-hover:scale-105`, `hover:border-primary/60`), so the rail ships no JavaScript of its own. `lg:sticky lg:top-8 lg:self-start` turns it into a sidebar from `lg`; below `lg` the page grid collapses and the same markup becomes the "keep reading" section under the story. `lg:self-start` is required — a stretched grid item cannot stick.

## Decisions & Gotchas
- The Pantheon install answers **403** on themed permalinks and only exposes `/graphql` publicly, so cards link to the local `/blog/[slug]` route (which renders the `content` field) rather than `post.sourceUrl` (`sourceUrl` is still kept for attribution).
- `remotePatterns` must use the object form **without** `search`: `new URL("https://images.unsplash.com/**")` infers `search: ""`, which rejects every Unsplash URL and makes the optimizer return `400 "url" parameter is not allowed` (verified against `next start`).
- `content` is requested in listing queries because WPGraphQL exposes no word count and the reading-time badge needs it.
- `page.tsx` exports its own `metadata`; `layout.tsx` still carries the create-next-app defaults.
- The per-card top-margin offset at `lg` was **removed on purpose** (conflicts with `.clinerules` "staggered post cards"). The stagger only works with intrinsically-sized cards: under `items-stretch` + the fixed-height card internals a top margin shortens the card inside its own row track and, because the image/title/excerpt blocks cannot compress, the footer gets clipped by `overflow-hidden`. The editorial asymmetry now comes from the oversized hero and the typographic hierarchy. If the offset is ever reinstated, it must be applied without layout impact (e.g. a `translate-y` on the row) and the card internals must go back to intrinsic sizing.
- Hero height control is **`lg:`-scoped on purpose**. Applying the requested unprefixed height/max-height pair (50vh / 500px, floor 380px) at every breakpoint clipped the hero on phones: with `height: 50vh` (333px on a 375×667 device) the box resolves to the 380px floor while the mobile content (badge + 3–4 line `text-4xl` headline + excerpt + wrapped CTA/meta ≈ 460–495px) is bottom-pinned inside an `overflow-hidden` frame, so the badge and the top of the headline were cut off. Base/sm therefore keep only the 380px floor with a content-driven height, and the clamp starts at `lg` (50vh, capped at 500px) then locks to a controlled 460px at `xl`.
- The cap is only safe because the content is *bounded*: the `lg`/`xl` floors (440 / 460px), the tighter `lg:gap-4` + `lg:p-10` rhythm and the clamps (`lg:line-clamp-3` headline, `lg:line-clamp-2` excerpt) hold the worst case at ~414px (`lg`) and ~452px (`xl`), inside the caps. Without the clamps a long hero headline (~4+ lines) would overflow the top of the box and be clipped. The `lg` headline steps down to `text-5xl` (the 60px `text-6xl` is kept from `xl`) for the same reason, so the 2K/4K/ultrawide rendering keeps the full editorial scale.
- Above-the-fold budget with the new geometry (1080p: masthead 65 + `pt-14` 56 + hero 460 + `gap-14` 56 + section header ~110 + `gap-8` 32 ≈ 779px): the "Latest stories" heading and the first ~300px of the card grid are visible on load, and on a 768px-tall laptop at `lg` the hero is 440px so the grid starts at ~759px.
- `mx-auto w-full max-w-[1600px]` is applied to `<main>`, the masthead inner container and the footer inner container together — capping only `main` would have left the masthead/footer full-bleed and misaligned at the edges. Content width tops out at 1472px (`lg:px-16` gutters), which keeps 4 cards at ~350px from `2xl`.
- Gotcha: Tailwind v4 auto-detects sources and **scans `AGENTS.md` too**, so any utility string written in this file is emitted into the CSS chunk — that is how the retired hero utilities survived in the stylesheet after the components stopped using them. Keep stale class literals out of the docs. That leak is not merely cosmetic: a malformed variant chain documented here kept feeding the broken marker pseudo-element selector (and its Lightning CSS warning) long after the component had stopped using it, so grep this file whenever the CSS parser complains about a class nobody writes any more.
- **The article URL moved to `/blog/[slug]`.** `post.href` in the data layer now builds `/blog/${slug}` and `next.config.ts` answers the retired `/posts/:slug` shape with a `permanent: true` redirect (verified **308** against `next start`), so old links, bookmarks and crawlers never hit a 404. The old route file was deleted instead of kept alongside: two routes rendering the same story would have doubled the SSG paths and produced duplicate content.
- **Tailwind Typography replaced the hand-written `.article-content` layer.** `@tailwindcss/typography@0.5.20` is a devDependency registered with `@plugin "@tailwindcss/typography";` in `globals.css` — Tailwind v4 has no `tailwind.config.js`/`plugins` array here, so the `@plugin` directive is the only correct way to install it. Keeping both systems would have produced conflicting list/code/quote rules, hence the deletion of the `@layer components` block. Verified in the emitted chunk: `.prose` (142 rules), `.prose-invert`, `.prose-indigo` and every `prose-*` modifier compile, and zero `.article-content` rules remain.
- **List-marker colour is a native Typography custom property, never a variant chain.** Tailwind Typography 0.5.20 has **no** `--color-prose-bullets` theme key (verified: its styles only set `--tw-prose-bullets` / `--tw-prose-counters` on `.prose`), so `@theme` cannot reach list markers. `src/app/globals.css` therefore ships one **unlayered** `.prose.article-prose` rule that repaints both properties with `var(--figma-primary)`, and `article-prose` is part of `ARTICLE_PROSE_CLASSES`; unlayered CSS outranks the plugin's utilities-layer declarations regardless of source order. Chaining the `marker` variant onto a `prose-*` element modifier is a trap: Tailwind emits a malformed pseudo-element selector with a trailing ` :is(...)`, which Lightning CSS reports as *2 warnings while optimizing generated CSS* (`Pseudo-elements like '::before' or '::after' can't be followed by selectors like 'Colon'`) — and `next dev`/Turbopack surfaces it as `Parsing CSS source code failed`. Neither the article route nor this file may contain that literal: the page class was already removed, yet the build kept emitting the broken selector because the chain was still written here, and Tailwind scans `AGENTS.md`.
- **Related-story strategy** (`getRelatedPosts` in the article page): same category first via `getPosts({ categoryName })` — WPGraphQL takes the *display name* (`"Tech News"` with a space works, verified live with 0 errors) — then backfilled with the newest posts from the rest of the newsroom, always excluding the story being read, capped at 3. The backfill costs nothing extra because both queries share the `wordpress:posts` cache tag, and a category filter that fails or matches nothing degrades to the latest stories instead of breaking the rail. Verified: a *Development* article shows 3 Development stories; the lone *Non classé* post shows the 3 latest.
- The article page has **no masthead** (unlike `/`, whose header/footer are page-local components): navigation is the back link at the top plus the "All stories"/"More stories" CTAs. If a shared header is ever extracted, it should move out of `src/app/page.tsx` into `src/components/blog/` and be used by both routes.
